## 우선순위

이 목록을 다 하자는 게 아니다. **막고 있는 것부터** 본다.

1. ~~사망 플래그·비밀번호 변경 이력 연동~~ — **해결.** 둘 다 데이터와 조회 메서드가
   이미 있었고 컨트롤러에서 하드코딩된 `false` 만 남아 있었다.
2. **API 스펙의 병합 반영** — 지금 스펙을 보고 붙이면 없는 서비스를 부르게 된다.
3. ~~검색 품질 측정~~ — **해결.** 남은 것은 주기 실행과 ES 하이브리드 실측이다.
4. ~~관리자 화면 직원 ID~~ — **해결.** 끊긴 곳이 다섯 군데였다. 화면 입력칸, 토큰
   미첨부, 프록시의 헤더 제거, 토큰 없을 때의 body 폴백, 그리고 틀린 클레임 이름
   (`empId` 를 안 찾아 고객 ID 인 `sub` 로 떨어지던 것).
5. ~~복식부기~~ — **해결.** 검증은 있었으나 여섯 곳이 변수를 자기 자신과 비교하고
   있었다. 이제 저장된 행을 읽어 묶음별로 확인한다.
6. ~~대사~~ — **해결.** 없던 기능이다. 불일치 5종을 잡아 적재하고 지표로 낸다.
   남은 것은 마감 배치 자동 실행이다.
7. ~~상담 서비스 인가~~ — **해결.** 조사해 보니 "고객 IDOR" 한 가지가 아니라
   엔드포인트 24개 중 인증을 요구하던 것이 5개뿐이었다. `POST /chatbot/transfer` 에
   남의 고객번호를 적으면 **그 사람 계좌에서 돈이 나갔고**, `PATCH /agents/{id}` 로
   아무나 상담원 비밀번호를 바꿀 수 있었다.

나머지는 "후속" 으로 적힌 대로 두어도 지금 무언가를 막지 않는다.
