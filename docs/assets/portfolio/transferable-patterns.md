# 도메인을 옮겨도 남는 것 — 이 레포 전체 기능의 재사용 지도

> 이 레포는 인터넷뱅킹을 구현했다. 그런데 만든 것 대부분은 **"돈" 이라는 낱말만
> 바꾸면 다른 도메인의 문제와 같다.**
>
> 판정 기준은 하나다: **규제가 은행이 아니어도 같은 문제가 생기는가.**
> 예금 이자 계산식은 안 남는다. "여러 시스템에 걸친 상태를 원자적으로 끝내는 법",
> "자동 판정을 사람이 뒤집을 수 있게 하는 법" 은 남는다.
>
> 컨트롤러 130여 개 · 엔드포인트 463개 · 서비스 5 + 사이드카 4개에서 골랐다.

## A. 거래 정합성 — "여러 곳이 함께 맞아야 하는 상태"

`services/core-banking/src/main/java/com/bank/payment/`

| 기능 | 구현 | 옮겨지는 곳 |
|---|---|---|
| **복식부기 검증** | `DoubleEntryVerifier` — 차변·대변 합이 0인지 묶음별로 확인 | 정산 플랫폼, 포인트/캐시 원장, 재고 이동 |
| **멱등성 키** | `IdempotentTransactionSaver` — 같은 키의 재요청은 같은 결과 | 결제 재시도, 웹훅 수신, 메시지 소비 |
| **Outbox 패턴** | `OutboxPublisher` — DB 커밋과 이벤트 발행을 한 트랜잭션에 | 이벤트 기반 아키텍처 전부 |
| **Saga + 보상** | `PaymentOrchestratorImpl` — 타행이체는 보상 트랜잭션 | 외부 시스템이 끼는 모든 다단계 처리 |
| **로컬 트랜잭션으로 되돌리기** | 자행이체를 서비스 병합으로 로컬화(`LocalLedgerAdapter`) | **분산 트랜잭션을 감수할 이유가 없는 곳을 찾아내는 판단** |
| **대사(reconciliation)** | `ReconciliationService` — 불일치 5종을 잡아 적재·지표화 | 정산 대사, 재고 실사, 외부 API 결과 대조 |
| **역분개** | `ReversalController` (스키마만) | 취소·환불이 있는 모든 원장 |

### 특히 옮겨 쓸 만한 판단 하나

병합 결정 문서(`docs/decisions/core-banking-merge.md`)의 논지가 **아키텍처 결정
기록의 본보기**다.

> 경계는 트랜잭션 요구가 아니라 **담당자 분담**을 따라 그어졌다.
> `X-Caller-Service` 헤더, A-1·B-3 같은 협상 번호가 그 흔적이다.

"마이크로서비스를 쪼갠 이유가 기술이 아니라 조직이었다" 를 증거로 짚고, **되돌린**
사례다. 반대 방향(쪼개기) 사례는 흔한데 이건 드물다.

`services/customer-service/` · `services/api-gateway/`

|---|---|---|

| **인증서 발급·폐기·PIN** | `CertIssueController`·`CertManageController` | PKI/디바이스 인증서를 쓰는 IoT·기업 SSO |

| **본인확인 만료·1회성** | `CUST_145/146` — 만료·재사용 거절 | OTP·매직링크 전부 |
| **접근 감사 로그** | `CustomerAccessLog` — 직원이 고객 정보를 **본 것**도 남긴다 | 의료기록 열람, HR 인사정보, 고객 상담 이력 |
| **Break-glass** | `BreakGlassService` — 비상 권한 상승 + 사후 감사 | 장애 대응 권한, 운영 긴급 접근 |

**"열람도 기록한다"** 가 옮겨지는 핵심이다. 수정 이력은 대부분 남기는데 **조회 이력을
남기는 시스템은 드물다.** 의료·인사·상담 도메인에서는 그게 규제 요구다.

## C. 심사·승인 워크플로 — "자동 판정을 사람이 뒤집는 구조"

`services/loan-service/`

| 기능 | 구현 | 옮겨지는 곳 |
|---|---|---|
| **트랙 분기** | TRACK_1 자동승인 / TRACK_2 자동반려 / TRACK_3 사람필수 | 모더레이션(자동삭제/자동통과/신고큐), 스팸, 부정거래 |
| **4-eye 승인** | `LoanReviewApproverService` — 승인자가 심사역 결정을 번복 가능 | 지출 결재, 배포 승인, 권한 부여 |
| **격리와 처분** | `dispose()` — 격리에 **나오는 길**을 만든다 | 자동 차단이 있는 모든 곳 |
| **채택률 계측** | `ReviewAdoptionMetrics` — AI 권고 ↔ 사람 결정 대조 | 추천 시스템, 코드 리뷰 봇, 자동 분류 |
| **편향 검사** | `bias/` + `AuditFairnessAgent` — 보호속성별 승인률 격차 | 채용, 대출, 보험, 광고 타겟팅 |
| **공정성 리포트·드리프트** | `FairnessReport`, `PsiDriftDetector` (PSI 기반) | 운영 중인 모든 ML 모델 |
| **섀도 모드·카나리** | `ShadowModeService`, `shadow/canary` | 모델 교체 전 비교 |
| **심사 검토 로그** | `ReviewCheckLogController` — 무엇을 확인했는지 | 감사 대응이 필요한 모든 판정 |

### 이 계열의 설계 문장

README 의 **"agents propose, humans dispose"** 가 코드로 강제된 형태다. 격리에
들어가는 길만 있고 **나오는 길이 없던** 것을 찾아 만든 것이 실제 작업이었다.

처분은 상태만 바꾸지 않는다. **격리를 푼 사실 자체가 감사 대상**이라 DB CHECK 로도
누가·언제·왜를 강제한다.

```sql
CHECK (disposition_cd IS NULL
       OR (disposed_at IS NOT NULL AND disposed_by IS NOT NULL
           AND length(btrim(disposition_note)) > 0))
```

그리고 **정상 판정만 격리를 끝낸다.** 재심사·조사 의뢰는 아직 열린 사안이라
`RESOLVED` 로 바꾸면 목록에서 사라지고 아무도 다시 안 본다.

## D. AI 에이전트 — 4종

### D-1. 조사 에이전트 (LangGraph) — `agents/fraud-investigation-agent/`

가장 이식성이 높다. **"제한된 예산으로 도구를 골라 가설을 좁히는 에이전트"** 의
완결된 형태다.

| 구성 | 파일 | 무엇 |
|---|---|---|
| 가설 공간 | `hypotheses.py` | 시나리오 후보 집합 |
| 도구 분별표 | `tool_matrix.py` | 도구마다 **어떤 시나리오 쌍을 가르는지** |
| 플래너 | `planner.py` | 다음 도구 선택 (LLM은 `{tool, reason}` 만 반환) |
| 스코프 | `scope.py` | 이 사건에서 볼 수 있는 범위 — **값으로 강제** |
| 채점 | `evaluation.py` | LLM 심판 없이 결정적으로 |
| 추적 | `tracing.py` | 자동 수집 없음 |

- **옮겨지는 곳**: 인시던트 조사(SRE), 보안 알럿 트리아지, 고객 이탈 원인 분석,
  품질 이슈 근본원인 추적
- **핵심**: 도구 호출이 **비용**인 문제라면 그대로다. "무엇을 부를까" 를 LLM 에게
  맡기되 **범위와 예산은 코드가 쥔다**

### D-2. 사전 심사 에이전트 — `agents/auto-loan-review/`

| 기능 | 구현 |
|---|---|
| 도구 레지스트리 | `AgentToolRegistry` — 목적분석·리스크도출 등 |
| 루프 가드 | 도구 ≤6 · LLM ≤2 · 턴 5 |
| 폴백 사유 | `FallbackReason` — **왜 자동 판정을 포기했는지** 를 남긴다 |
| PII 유출 차단 | `PiiMaskingFilter`, `PiiLeakageException` — 나가는 길목에서 |
| 거절 사유 생성 | `RejectionNoticeService` — 사람이 읽을 문장으로 |

**`FallbackReason` 이 특히 옮겨진다.** 대부분의 시스템은 "자동 처리 실패" 를 한 종류로
묶는데, 왜 포기했는지를 나눠 두면 **어디를 고쳐야 자동화율이 오르는지**가 보인다.

### D-3. 상담 에이전트 — `agents/consultation/`

시나리오 트리 + LLM 하이브리드. 순수 LLM 챗봇보다 이식 가치가 높다.

| 기능 | 파일 | 옮겨지는 곳 |
|---|---|---|
| 시나리오 노드·버튼·플로 | `chatbot_node`·`node_button`·`node_flow` | 정형 절차가 있는 모든 상담 |
| 의도 분류 → 기능 라우팅 | `IntentClassifier` + `features/` | 고객지원 봇 |
| 상담원 이관(handoff) | `ChatConsultation` — 대기·연결·재배정·이탈 계측 | 봇→사람 전환이 있는 모든 곳 |
| 목표 상담 | `savings_goal.py` — 목표액·기간에서 역산 | 피트니스·학습·저축 등 목표 앱 |
| 소비 패턴 분석 | `spending_pattern_agent.py` | 사용량 분석, 이상 소비 탐지 |
| 만기 안내 | `maturity_agent.py` | 구독 갱신, 보증 만료 |
| 상품 비교 | `product_compare.py` | 요금제·플랜 비교 |
| 서류 업로드 | `chatbot_document` | 문서 제출이 있는 모든 상담 |

**이관 계측**(대기시간·이탈·재배정·동시 상담 수)이 눈에 잘 안 띄는 자산이다.
봇 도입 성과를 "봇이 몇 % 처리했나" 가 아니라 **"사람에게 넘어간 건이 어떻게 됐나"**
로 보게 해 준다.

### D-4. 서류 검증 에이전트 — `agents/doc-agent/`

| 기능 | 디렉터리 | 옮겨지는 곳 |
|---|---|---|
| 제출·검토 흐름 | `submission`·`review` | 신원확인(KYC), 보험 청구, 채용 서류, 세금 |
| 위조 점수 | `forgery` | 이미지 변조 탐지가 필요한 모든 업로드 |
| 검증 규칙 | `verify` | 필수 항목·유효기간·발급기관 대조 |
| **보존 정책** | `retention` | GDPR/개인정보 파기 의무가 있는 모든 저장소 |
| 봉투 암호화 (Vault) | `infra` | 민감 파일 저장 |

**`retention` 이 특히 드물다.** 대부분 "저장" 은 만들고 "언제 지우나" 는 안 만든다.

## E. 계약 생애주기 — "가입에서 끝날 때까지"

| 기능 | 구현 | 옮겨지는 곳 |
|---|---|---|
| 상품 카탈로그·특약 | `ProductController`·`SpecialTermController` | 요금제·플랜·옵션 |
| 가입 대상 판정 | `JoinTargetController`·`TargetGroupController` | 프로모션 자격, 베타 대상 |
| 우대 조건 | `PreferentialRatePolicyController` | 할인·등급 혜택 |
| 납입 스케줄 | `PaymentScheduleController` — 회차·연체·자동이체 실패 | 구독 청구, 할부, 회비 |
| **중도해지 정산** | `EarlyTerminationEstimator` — 경과 비율 → 이율 → 예상 실수령 | 구독 중도해지 환불, 위약금 |
| 만기 자동 전이 | `MaturityController`·`MaturityBatchController` | 구독 갱신, 라이선스 만료 |
| 부분·중도 상환 | `PartialRepaymentController`·`PrepaymentController` | 선결제, 부분 환불 |

### 중도해지 정산이 옮겨지는 이유

세 가지를 함께 해결한 사례다.

1. **정책을 표에 둔다** — 코드에 숫자를 박으면 정책 변경마다 배포해야 하고 **고객에게
   보여 준 값의 근거가 안 남는다**
2. **"예상" 이라고 밝힌다** — 확정 금액처럼 보여 주면 1원만 어긋나도 속였다고 읽힌다
3. **구간이 없으면 조용히 메우지 않고 실패한다** — 임의로 메우면 근거 없는 값을
   보여 주고도 아무도 모른다

### 이 계열에서 배운 설계 규칙 셋

- **개인 메모와 시스템 값을 섞지 마라.** 같은 컬럼이 한 화면에서는 "출금통장표시내용",
  다른 화면에서는 "메모" 로 렌더링되고 있었다. 편집 버튼을 붙였다면 **실제로 상대방에게
  보낸 문구를 위조**하는 것이 됐다
- **신청과 발송을 나눠라.** 입금통보는 신청까지만 동작한다. 발송 경로가 없으면
  그렇다고 적는다 — 신청만 받고 안 보내면 고객은 신청됐다고 믿고 기다린다
- **예약은 서버가 영업시간을 본다.** 화면만 막으면 API 직접 호출로 뚫린다.
  마감 시각 자체도 받지 않는다 — 16:00 마감에 16:00 상담은 앉을 시간이 없다

## H. 거버넌스 — 앞의 전부를 지탱하는 것

이 레포에서 반복해 만난 실패는 하나였다. **컴파일되고, 렌더링되고, 테스트가
통과하는데 아무 일도 안 하는 코드.**

### H-1. 불변식을 테스트로 못 박기 — `common/.../monitoring/` 9종

| 테스트 | 실제로 잡은 것 |
|---|---|
| `FrontendGatewayOnlyTest` | 클라이언트 8개가 게이트웨이 우회 → **인가가 통째로 무의미** |
| `GatewayRouteCoverageTest` | `/api/v1/banking/**` 무라우트 — 목록이 늘 비어 보임 |
| `ApiSpecFreshnessTest` | 없는 서비스 4종, 엔드포인트 91개 누락 |
| `PlanStatusTest` | 계획서 33건 중 2건이 코드와 **반대로** 적혀 있었음 |
| `EntitySchemaConsistencyTest` | 테이블 부재 → **승인 토큰이 항상 500**, 소액 초과 이체 전면 불가 |
| `SidecarExposureTest` | 사이드카 호스트 포트 노출 |
| `ComposeNetworkReachabilityTest` | 망 격리 |
| `DockerBuildContextTest` | 빌드 컨텍스트 누락 |
| `ThemeTokenSyncTest` | 색 토큰 두 벌 어긋남 |

**아홉 중 은행이라서 필요한 것은 하나도 없다.**

> 함께 옮겨야 하는 것: **빌드 입력 선언.** 검사가 읽는 파일을 태스크 입력으로
> 선언하지 않으면 `UP-TO-DATE` 로 건너뛴다. **지키라고 만든 검사가 조용히 안 도는
> 상태.** 이 레포에서 다섯 번 겪었다.

### H-2. 변이 검증

규칙을 만들면 **깨 보고 테스트가 우는지 확인한 뒤 되돌린다.**

실제로 복식부기 검증 여섯 곳이 **변수를 자기 자신과 비교**하고 있었다. 전부
통과했고, 아무것도 안 지키고 있었다.

### H-3. 관측 기본값 뒤집기 — `harness_core/tracing.py`

벤더 `@observe` 는 인자·반환값을 **자동으로** 싣는다. 계측을 켜는 순간 추적 저장소가
데이터 사본이 된다. 여기서는 **아무것도 자동으로 싣지 않고** 실을 것을 명시한다.

### H-4. 가명처리 — `harness_core/pii.py`

지우면 못 쓴다. `[MASKED]` 로 지우면 "같은 사람의 건 3개" 를 묶을 수 없다.
HMAC 이면 묶을 수는 있고 되돌릴 수는 없다. 소금 미설정 시 **임의 값으로 시작해 그
사실이 드러나게** 한다.

### H-5. 결정적 평가 — `evaluation.py`

LLM 심판을 안 쓰는 이유 둘: ① 심판에 넘기는 것이 곧 데이터 ② 같은 입력에 같은
점수가 안 나오면 감사에서 설명할 수 없다. **정답지를 만들 수 있으면 심판이 필요 없다.**

### H-6. 문서를 생성물로

`api-spec.md` 는 "자동 추출" 이라 적혀 있었는데 **추출기가 없었다.** 뽑는 방법 자체를
남기고 테스트로 못 박았다. 계획 문서 33건도 상태 어휘를 넷으로 고정했다 —
**상태가 사실인지는 일부러 검사하지 않는다.** 기계가 판정하려 들면 거짓 경보가 난다.
