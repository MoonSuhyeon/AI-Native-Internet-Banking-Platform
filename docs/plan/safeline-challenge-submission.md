# 첨부 1 — 기획서

## 1. 서비스 명칭
세이프라인(SafeLine) — AI 이상거래 조사·대응 에이전트

## 2. 아이디어 기획 핵심내용 (요약)
이상금융거래가 탐지되었을 때 은행 직원이 빠르게 상황을 확인하고 안전하게 대응할 수 있도록 돕는 AI 금융 보안 에이전트입니다.

기존에는 이상거래가 발견되면 직원이 거래내역, 계좌정보, 기기·인증 기록 등을 여러 곳에서 직접 확인해야 합니다. 세이프라인은 AI가 필요한 정보를 자동으로 조사하고 위험 근거와 조사 결과를 하나의 리포트로 정리합니다.

특히 위험 점수만으로 우선순위를 정하지 않고, 추가 확인이 필요한 중요한 상황을 함께 고려합니다. 예를 들어 사망한 고객의 계좌에서 출금이 발생한 경우, 금액이 크지 않더라도 거래의 정당성을 확인할 필요가 있습니다.

AI는 조사와 대응 방안을 제안하지만, 거래 보류·차단 등의 최종 결정은 은행 직원이 직접 승인합니다. AI의 조사 과정과 직원의 판단 결과는 감사 로그에 기록하여 사후 검증이 가능하도록 합니다.

## 3. 문제 정의 및 제안 배경

### 문제점
1. **탐지 후 조사에 시간이 걸림** — FDS가 이상거래를 찾아도 직원은 여러 시스템에서 관련 정보를 직접 확인하며 사건의 전체 상황을 다시 파악해야 합니다.
2. **위험 점수만으로는 중요한 거래를 판단하기 어려움** — 금액이나 거래 패턴만으로는 모든 금융사고 위험을 설명하기 어렵습니다. 예를 들어 사망한 고객의 계좌에서 출금이 발생하면 거래 금액과 관계없이 고객 상태와 거래의 정당성을 확인해야 합니다.
3. **AI 판단을 그대로 믿기 어려움** — AI가 위험하다고 판단하더라도 어떤 정보를 확인했고 왜 그런 결과가 나왔는지 알 수 없다면 직원이 최종 결정을 내리기 어렵습니다.

### 대상 고객 및 채널 선정 배경
주요 사용자는 은행의 이상거래 대응 업무를 담당하는 직원입니다.
소비자는 인터넷·모바일뱅킹에서 이상거래가 감지되었을 때 거래 확인이나 상담 연결 등의 서비스를 이용합니다. 이를 통해 소비자의 피해를 예방하면서, 직원은 AI가 정리한 조사 결과를 바탕으로 빠르게 대응할 수 있습니다.

## 4. 서비스 컨셉 및 차별성
기존 FDS가 "이 거래가 이상한가?"를 판단한다면, 세이프라인은 "왜 이상한지 확인하기 위해 무엇을 조사해야 하는가?"까지 지원합니다.

| 구분 | 기존 FDS | 세이프라인 |
|---|---|---|
| 역할 | 이상거래 탐지 | 탐지 + 추가 조사 |
| 판단 | 위험 점수 중심 | 위험 신호 + 추가 증거 |
| 조사 | 직원이 직접 확인 | AI가 관련 정보 조사 |
| 결과 | 위험 여부 | 위험 근거 + 조사 결과 |
| 실행 | 시스템 또는 직원 처리 | AI 제안 + 직원 최종 승인 |
| 기록 | 탐지 결과 중심 | 조사·판단·처리 과정 기록 |

핵심은 AI가 금융거래를 대신 결정하는 것이 아니라, 조사에 필요한 일을 대신하고 사람의 최종 판단을 돕는 것입니다.

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안

### 활용 데이터
- 거래 이력: 수취인, 금액, 시간, 거래 빈도
- 고객·계좌 정보
- 기기·접속 정보: IP, 기기 변경 이력
- 인증 이력
- FDS 위험 점수 및 탐지 결과
- 공개된 금융사기·보이스피싱 피해 사례

MVP에서는 실제 금융계좌 대신 가상(mock) 데이터를 사용합니다.

### 생성형 AI 활용 방안
AI 조사 에이전트가 이상거래와 관련된 거래·계좌·기기·인증 정보를 순서대로 확인합니다. 확인한 내용을 바탕으로 주요 위험 신호와 조사 근거를 자연어로 정리하고, 직원이 취할 수 있는 대응 방법을 제안합니다. 생성형 AI는 판단을 보조하는 역할만 수행하며, 거래 보류·차단 등 실제 조치는 직원이 최종 승인합니다.

## 6. 기대 효과 및 확장 가능성

### 기대 효과
- **소비자**: 이상거래 발생 시 추가 인증이나 상담 연결 등을 통해 금융사고 피해를 예방할 수 있습니다.
- **금융기관**: 직원이 여러 시스템의 정보를 직접 찾아보는 시간을 줄이고, 중요한 위험 신호를 빠르게 확인할 수 있습니다.
- **직원**: AI가 조사 결과와 근거를 정리해 주므로 데이터 수집보다 최종 판단과 대응에 집중할 수 있습니다.
- **내부통제**: AI의 조사 과정과 직원의 승인·반려 결과를 기록하여 사후 검증이 가능합니다.

### 확장 가능성
카드 이상결제, 보험사기, 대출 부정 이용 등 다른 금융 리스크 조사에도 적용할 수 있습니다. 또한 직원의 승인·반려 결과를 축적하여 이상거래 탐지 및 조사 정책을 지속적으로 개선할 수 있습니다.

## 7. 팀 기술 역량
본 팀은 사전에 FDS 에이전트, HITL 승인 게이트, RBAC 기반 권한 제어, 감사 로그를 갖춘 AI 네이티브 뱅킹 플랫폼을 설계·구현한 경험이 있습니다. 이를 바탕으로 이상거래 탐지부터 AI 조사, 직원 승인, 감사 로그까지 연결되는 실제 작동 가능한 금융 AI MVP를 구현할 수 있습니다.

# 첨부 2 — 기능 명세서

## 1. MVP 구현 범위

### 구현 완료
- **거래 사전점검(PreCheck)**: 송금 정보를 확인하여 위험도를 산정하고 정상·추가인증·지연·차단 단계로 분기
- **이상거래 대응 안내 UI**: 위험 거래 발생 시 추가 인증, 거래 취소, 상담 연결 등의 방법을 안내
- **AI 이상거래 조사 에이전트**: 거래·계좌·기기·인증 정보를 자동으로 조회하고 이상거래의 위험 근거를 조사
- **상담원 승인 콘솔**: AI 조사 결과와 근거를 확인한 후 거래 승인·보류·차단 등을 최종 결정
- **감사 로그**: AI 조사, 직원 판단, 승인·반려 및 처리 결과를 기록하고 조회

### 미구현 / 향후 구현 예정 — 제외
- 피드백 기반 자동 학습
- 승인·반려 결과의 모델 자동 반영
- 운영 지표 대시보드

## 2. 주요 기능 목록

| 기능명 | 기능 설명 | 관련 화면 | 구현 상태 |
|---|---|---|---|
| 거래 사전점검 | 송금 시 위험 신호를 확인하고 대응 단계로 분기 | 송금 화면 | 완료 |
| 이상거래 대응 안내 | 위험 거래 발생 시 추가 인증·취소·상담 방법 안내 | 송금 팝업 | 완료 |
| AI 조사 에이전트 | 거래·계좌·기기·인증 정보를 자동 조사 | 백엔드 | 완료 |
| 조사 결과 리포트 | AI가 확인한 위험 신호와 근거를 정리 | 상담원 콘솔 | 완료 |
| 상담원 승인 콘솔 | 조사 결과를 확인하고 승인·반려 처리 | 상담원 콘솔 | 완료 |
| 감사 로그 | 조사 및 승인·반려 과정을 기록·조회 | 로그 화면 | 완료 |
| 피드백 기반 학습 | 승인·반려 결과를 탐지 개선에 반영 | - | 미구현 |

## 3. 사용자 이용 흐름
1. 배포 URL 접속 후 테스트 계정으로 로그인
2. 송금 화면에서 수취인과 금액 등 이체 정보 입력
3. 시스템이 거래 정보를 확인하고 위험도를 산정
4. 이상거래가 의심되면 추가 인증·취소·상담 연결 등의 방법 안내
5. 상담 연결을 선택하면 해당 거래가 직원 화면으로 전달
6. AI 조사 에이전트가 거래·계좌·기기·인증 정보를 확인하고 조사 결과 작성
7. 직원이 AI가 수집한 근거와 조사 결과 확인
8. 직원이 거래 승인 또는 보류·차단 등의 조치 결정
9. 처리 결과와 조사·판단 과정이 감사 로그에 기록

**테스트 계정**: `employee01` / `Employee1234!`

## 4. AI 및 데이터 처리 방식

### AI 역할
- **이상거래 조사**: FDS에서 이상 신호가 발견된 거래의 관련 정보를 추가로 조회하여 위험 상황을 조사합니다.
- **근거 정리**: 거래·계좌·기기·인증 정보를 종합하여 주요 위험 신호를 직원이 이해하기 쉽게 정리합니다.
- **대응 제안**: 조사 결과에 따라 추가 인증, 거래 보류, 상담 연결 등의 대응 방법을 제안합니다.
- **최종 결정**: AI는 조사와 제안만 수행하며 거래 승인·보류·차단은 직원이 최종 결정합니다.

### 입출력 데이터
- **입력**: 거래 정보, 고객·계좌 정보, 기기·접속 정보, 인증 이력, FDS 탐지 결과
- **출력**: 위험도·위험 단계, 조사 근거, 위험 시나리오, 대응 방안, 직원용 조사 리포트

### 개인정보·민감정보 처리
실제 계좌번호와 주민등록번호 등 민감정보는 사용하지 않으며, MVP에서는 가상(mock) 데이터를 사용합니다.

## 5. MVP 검증 방법

### 테스트 계정
`employee01` / `Employee1234!`

### 샘플 입력값 및 예상 결과
- 송금 화면에서 특정 조건의 거래를 입력하면 이상거래 위험 신호가 발생합니다.
- 상담 연결을 선택하면 해당 거래가 직원 화면으로 전달됩니다.
- AI 조사 에이전트가 관련 거래·계좌·기기·인증 정보를 확인하고 주요 위험 신호와 조사 근거를 정리합니다.
- 직원은 조사 결과를 확인한 후 거래 승인 또는 보류·차단 등의 조치를 선택합니다.
- AI의 조사 과정과 직원의 최종 판단은 감사 로그에 기록됩니다.

### 실행 환경 제한사항
최신 버전 Chrome 브라우저 기준으로 테스트되었으며 모바일 브라우저에서는 일부 화면이 최적화되지 않을 수 있습니다.

### MVP 단계 제한사항
- 실제 은행 계좌 및 금융거래와 연결하지 않고 가상(mock) 데이터 기반으로 동작합니다.
- 실제 금융거래를 수행하지 않으며, AI의 판단은 금융기관의 최종 의사결정을 대신하지 않습니다.
- 실시간 대량 트래픽 처리 성능은 검증되지 않았습니다.
